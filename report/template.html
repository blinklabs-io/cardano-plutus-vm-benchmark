How it is measured

Every VM runs inside one Docker container, one VM at a time, using its own benchmark framework for warm-up and iteration counts. The decode + evaluate view times decoding each whole .flat program, including its Data arguments, and evaluating it. The evaluate-only view decodes the program before timing.

Interpreters and compilers do different work: llvm-uplc and the Scalus JIT compile each program to native or JVM code before timing, so they appear only in the evaluate-only view. VMs are ranked by the geometric mean of their times; a program a VM fails counts at the slowest successful time for that program.

Scalus, Julc and Chrysalis take three measurement samples per program, so their numbers carry more uncertainty. The methodology describes each VM's harness and the known limitations.
